# VazhiAI

**AI-powered career guidance, roadmap, and self-study platform.**

VazhiAI helps students, working professionals, and job seekers across *any* field — not just CS/IT — get a personalized career direction, a day-by-day learning roadmap generated by AI, daily progress tracking with quizzes, an AI mentor to talk through doubts, an ATS-friendly resume builder, and on-demand AI-generated study material.

## Features

### Account & Authentication
- Email/password signup and login, with passwords hashed via bcrypt (never stored in plain text).
- Session handling via short-lived, HTTP-Only, Secure access tokens plus a rotating refresh token — tokens are never exposed to client-side JavaScript, closing off the usual XSS token-theft path.
- Forgot-password flow via a one-time password (OTP) emailed to the user, with expiry, single-use enforcement, and brute-force lockout after repeated wrong attempts.
- Rate limiting on all authentication-sensitive endpoints (login, signup, OTP request/verify, password reset, logout).

### Onboarding
- A guided, multi-step onboarding wizard that adapts to the user's situation: Student, Working Professional, or Job Seeker.
- Supports every major field/domain — Computer Science & IT, Mechanical, Civil, ECE, EEE, Arts & Science, Commerce, and more — each with its own relevant tools, platforms, and career goals, rather than a one-size-fits-all CS-centric flow.
- Captures known tools, target skills, interests, certifications, and current challenges to give the AI real context.

### AI Career Suggestions
- Generates 3–4 personalized career path suggestions based on the user's full profile, powered by an LLM (Groq) with domain-aware prompting.
- Conversational refinement — users can chat to ask for different options ("more beginner-friendly", "less coding-focused", "higher salary"), and the assistant regenerates suggestions on request.

### AI-Generated Roadmaps
- Once a path is chosen, an AI generates a full day-by-day curriculum outline sized to the user's chosen duration, pace, and experience level.
- Outline generation and per-day content generation both run as background jobs so the UI doesn't block on slow LLM calls — the frontend polls until content is ready.
- Each day includes curated learning resources, practice problems (deduplicated across the whole roadmap so nothing repeats), an MCQ test, a coding assignment, and revision tasks.
- Practice-problem links are automatically sanitized to point at safe, working search pages (LeetCode, HackerRank, GeeksforGeeks, Codeforces, YouTube) instead of potentially broken deep links.

### Explore Paths (Roadmap Chatbot)
- A conversational assistant that can make minor tweaks to the existing roadmap, restructure it more significantly, or generate an entirely new roadmap — all through natural conversation, with explicit confirmation before anything destructive happens.
- Smart caching: when a roadmap is modified, only the days that actually changed have their detailed content regenerated; unaffected days keep their existing content.

### Daily Progress & Quizzes
- Per-day checklist of tasks and practice problems, with free-form notes.
- Timed multiple-choice quizzes per day, auto-scored, with per-question review of correct vs. selected answers.
- Progress history and test scores are available on the dashboard.

### AI Mentor Chat
- A context-aware chat assistant tied to the user's active roadmap and current day, so it can answer questions with full awareness of what the user is studying.

### Resume Builder
- Structured resume builder (education, projects, experience, skills).
- AI-powered resume optimization tailored to a target role, aimed at producing ATS-friendly phrasing.
- Client-side PDF export.

### Study Material Generator
- On-demand AI-generated study material (Markdown) for up to 5 topics at a time, with configurable difficulty, education level, output language, and length (short/medium/detailed).
- History of previously generated material, with the ability to revisit or delete past entries.

### Demo Course (Public Preview)
- An unauthenticated, fully static preview of the roadmap/day-plan experience using sample data — no sign-up, no API calls, nothing saved — so visitors can see what the product feels like before creating an account.

### Dashboard
- At-a-glance view of the user's active roadmap, recent progress, and quiz scores.

### Mentors *(in progress)*
- A planned feature for connecting users with mentors in their field. The UI shell exists today; the actual mentor-matching network is not yet live.

## Getting Started

### Prerequisites
- Python 3.10+
- Node.js 18+
- A PostgreSQL database (for production/local persistence)
- A Groq API key

### Backend Setup

```bash
cd backend
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

pip install -r requirements.txt

# Configure environment (see Environment Variables below)
cp .env.example .env           # then fill in your own values

# Apply database migrations
python migrate.py upgrade

# Start the API server
uvicorn main:app --reload --port 8000
```

The interactive API docs are available at `http://localhost:8000/docs` by default. Set `ENVIRONMENT=production` to disable them in a deployed environment.

### Frontend Setup

```bash
cd frontend
npm install

cp .env.local.example .env.local   # then fill in your own values

npm run dev
```

The app will be available at `http://localhost:3000`.

### Quickstart (both at once)

From the project root, `start.sh` (macOS/Linux) or `start.bat` (Windows) will set up and launch both the backend and frontend together.

## Environment Variables

No real values are included here — copy the `.env.example` files and fill in your own.

**Backend (`backend/.env`)**

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string |
| `JWT_SECRET_KEY` | Secret used to sign access/refresh tokens — required, no default |
| `GROQ_API_KEY` | API key for Groq LLM calls |
| `ALLOWED_ORIGINS` | Comma-separated list of allowed frontend origins (CORS) |
| `COOKIE_SECURE` | Set to `false` only for local HTTP development |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` | Outbound email config for password-reset OTPs |
| `SENTRY_DSN` | Optional — enables error monitoring |
| `ENVIRONMENT` | Set to `production` to disable public API docs |
| `DISABLE_RATE_LIMIT` | Test/CI only — never set in production |

**Frontend (`frontend/.env.local`)**

| Variable | Purpose |
|---|---|
| `NEXT_PUBLIC_API_URL` | Base URL of the backend API |

## API Overview

All authenticated routes expect an HTTP-Only session cookie (set automatically on login/signup) and are rate-limited where sensitive or LLM-backed.

| Group | Prefix | Examples |
|---|---|---|
| Auth | `/auth` | signup, login, refresh, logout, me, profile |
| Account Recovery | `/auth` | forgot-password, verify-otp, reset-password |
| Onboarding | `/onboarding` | complete, profile |
| Suggestions | `/generate-suggestions` | AI career suggestions |
| Chat | `/chat` | refine-suggestions, message, history, explore-paths |
| Roadmaps | `/roadmaps` | create/list/active roadmap, day details, progress, tests |
| Resume | `/resume` | optimize |
| Study Material | `/study-material` | generate, history, fetch, delete |

Full request/response schemas are available via the interactive docs (`/docs`) when running in a non-production environment.

## Security

A non-exhaustive summary of what's already in place:

- Passwords hashed with bcrypt; JWTs signed with an explicitly allow-listed algorithm.
- Access tokens are short-lived; refresh tokens are rotated on every use and revoked on logout.
- Auth cookies are HTTP-Only so tokens are never reachable from JavaScript.
- Rate limiting on all authentication, password-reset, and LLM-backed endpoints.
- Per-user data isolation enforced at the query level across roadmaps, progress, chat history, resumes, and study material.
- User-supplied content is HTML-escaped before rendering to prevent XSS.
- Structured logging with request IDs; internal error details are never leaked to API responses.
- Scheduled cleanup of expired refresh tokens and password-reset OTPs to prevent unbounded database growth.

This project has been through multiple rounds of security and scalability review; see the project's internal change history for details.
